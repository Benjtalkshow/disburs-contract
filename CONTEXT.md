## What this repo is

Soroban (Rust) smart contracts for **Disburs** — on-chain payroll that pays
contractors in a token (USDC) on Stellar. It is one of three separate repos:

- **disburs** — Next.js frontend (private for now, planned public)
- **disburs-backend** — NestJS + Prisma + Postgres (private by design; holds
  encryption/secrets logic)
- **disburs-contract** — this repo (public)

They're separate because GitHub visibility is per-repo: the backend must stay
private while the contracts are public.

## The payroll contract, in brief

State (on-chain): `Admin` (employer), `Token` (payout token, e.g. USDC SAC),
and `Salary(worker)` per worker.

Entry points on `main` today: `__constructor(admin, token)`, `deposit`,
`set_salary`, `pay`, `treasury_balance`, `salary_of`, `get_admin`, `set_admin`.
PR #2 adds `withdraw`.

Errors are stable `u32` codes — never renumber: `NotInitialized (1)`,
`InvalidAmount (2)`, `NoSalarySet (3)`, `InsufficientTreasury (4)`.

Every state-changing call authorizes the party that must consent — admin for
payroll ops, the sender for deposits. Money moves via the SEP-41 token
interface, so any compliant token works.

## Key decisions & rationale

- **soroban-sdk pinned to `22.x`** (not the latest 27.x). 27 requires Rust 1.93;
  local toolchain is 1.90. 22 has everything we need (`__constructor`,
  `env.register`, `register_stellar_asset_contract_v2`) and builds on stable.
- **ed25519-dalek pinned to `2.2.0`** in `Cargo.lock`. Its `3.0.0` release breaks
  soroban-env-host's test utilities (a `rand_core`/`CryptoRng` trait mismatch).
  `Cargo.lock` is committed on purpose so this stays reproducible.
- **wasm target is `wasm32v1-none`** (the modern Soroban target), pinned in
  `rust-toolchain.toml`. Not the older `wasm32-unknown-unknown`.
- **Module layout**: thin `lib.rs` + `errors.rs` + `storage.rs` + `test.rs` per
  contract. Admin/token in instance storage, salaries in persistent storage.
- **`no_std`**, and a small-wasm release profile (`opt-level = "z"`, `lto`,
  `panic = "abort"`, stripped, `overflow-checks` on).
- **`test_snapshots/` is gitignored** — auto-generated by `cargo test`, not
  tracked.

Reference points used while building: `boundless-contract` (local, for Soroban
conventions) and `zk-payroll-contracts` (local at
`/Users/apple/Documents/Projects/zk-payroll-contracts`, a fuller ZK payroll
system — payroll_registry, payment_executor, proof_verifier, audit_module,
circom circuits). The README's phase structure is our own; don't clone theirs.

## Roadmap (phases to completion)

1. **Payroll core** — shipped (this repo).
2. **Registry & batch runs** — a worker directory + one call that settles a whole
   run, per-worker events. Removes the one-at-a-time `pay` limit.
3. **Conditional releases** — pay against milestones/approvals, not a flat salary.
4. **Private salaries** — the point of the whole thing: salaries as commitments
   (not plaintext) + an on-chain proof verifier (Groth16 / BN254, Poseidon) +
   view keys for audit. This is the phase that pulls in Node.js and Circom.
   "Complete" = private payroll running end to end.

Each phase is its own contract under `contracts/*` composed with payroll.

Likely next concrete task: scaffold the **registry / batch-pay** contract
(Phase 2).
